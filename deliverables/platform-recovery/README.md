## WebSocket revoke semantics

The implemented contract is failure-preserving post-commit WebSocket close propagation with
explicit degraded reporting and retry-preserving registry state.

A durable DB revoke/change commits before `close_all(session_id)`. Failed/unattempted registry
connections remain available for a later explicit close attempt. Slice E does **not** implement an
automatic retry timer, queue, worker or cross-process propagation.

In this rehearsal an already-open target WebSocket received the registry's normal close (`1000`),
while a later handshake using the old revoked identity was rejected with `1008`. These are distinct
observations: the contract requires post-commit termination and rejection, not one shared close code.

## Safe rehearsal procedure

1. Schedule a maintenance window and stop platform writers before backup.
2. Keep dump/runtime artifacts outside Git and remove them after rehearsal.
3. Confirm the exact public recovery checkpoint and clean tree.
4. Set `SUPERSONIC_ALLOW_DB_RESTORE=1` only for the isolated restore invocation.
5. Use a distinct `RESTORE_DATABASE_URL` ending `_restore_test`.
6. Verify checksum and repository revision before destructive restore.
7. Restore with `--clean --if-exists --no-owner --no-acl --single-transaction`.
8. Verify revision, exact counts and invariants.
9. Start the restored app and verify identity/Audit/revoke/GP05 acceptance.
10. Sanitize retained evidence and remove temporary credentials/databases/roles.

The restore script does not create or drop a whole database and does not silently run Alembic upgrade.

## Sanitization boundary

Never record passwords, tokens, cookies, token digests, DSNs, host/user details, private payloads,
raw stderr, absolute local paths, SQL exports or database dumps.

Screenshots contain synthetic identities only.

# 开发规范

## 1. 产品与技术事实的证据顺序

本节仅用于产品事实、实现事实或技术判断的证据取舍；工作流、安全、权限、受保护分支、发布和破坏性操作以根部 [`AGENTS.md`](../AGENTS.md) 为准。

1. 用户在当前任务中的明确决定；
2. 可运行代码、测试与实际工具输出；
3. 根目录和局部 `AGENTS.md`；
4. 当前项目进度、已接受的 ADR 与当前方向文档；
5. 早期报告、旧 Demo 和聊天摘要。

冲突时不得静默选择。记录冲突、采用证据更强的一方，并更新过时文档。

## 2. 项目环境与架构边界

本仓库默认是本地、单用户、可信环境的毕业设计原型，不是公共云或量产车辆系统。

- Figma/Make：设计 Token、组件、四屏稿和 Prototype；不承担运行时数据逻辑；
- React 前端：呈现、交互、动效和降级；不复制后端业务真相；
- FastAPI 后端：车辆状态、场景和多屏广播的唯一权威来源；
- JSON：当前 Profile、场景和本地降级路线配置；
- WebSocket：连续全量 snapshot；HTTP：命令、配置和资源；
- 持久化、真实地图、Vision、Web3D 和 AI：只有独立 Issue 触发后才进入当前范围。

不因为依赖已声明、文档曾规划或界面存在占位，就把能力写成已实现。

## 3. 前端规范

- TypeScript strict，不以 `any` 绕过领域建模；外部数据先校验再进入 Store；
- 组件按领域含义命名，不按临时视觉位置命名；
- 页面不直接散落车型判断；差异通过 Profile、Token 和组件 Variant 表达；
- 关键驾驶信息具有无 3D、无动画、无网络情况下的降级表现；
- Three.js、React Three Fiber 和 ECharts 是按需使用的增强工具，不是每个端点必须使用的基础设施；
- 三维资源必须异步加载，不能阻塞仪表、HUD 和告警；
- 新交互至少覆盖成功、错误、加载、空数据和不可用状态中的适用项；
- 无效 JSON、错误协议或不完整 snapshot 不能进入 Store；
- Overview 不挂载命令控件；Control 不直接修改本地业务状态。

## 4. 后端规范

- Pydantic 模型定义跨层契约；接口变更同步更新前端类型和测试；
- 状态转换保持确定性；随机演示数据必须支持固定种子或可复现场景；
- Mock 与未来真实适配器使用同一稳定领域模型；
- API 错误使用稳定结构，不把堆栈或密钥返回前端；
- 长任务和外部调用设置超时、取消和可理解的降级结果；
- 端点权限由服务端拥有的请求或连接上下文确定，不只信任请求体字段；
- 持久化若启用，不作为实时状态源，失败不得阻断四屏告警；
- 外部地图、模型或 AI 缺失时，应用必须保持明确的 Mock/降级路径。

## 5. HMI 与设计规范

- 安全相关信息优先于装饰性内容；HUD 只保留驾驶中必要内容；
- 告警至少使用图形、文字、位置或动效中的第二种通道，不只依赖颜色；
- 四屏共享设计语言，但信息职责不同，禁止简单复制同一页面；
- 目标是原创高端 HMI；可以学习成熟产品的克制与系统性，不复制商标、图标、布局和资产；
- 每个 Figma 组件应能映射到代码组件、数据字段和可测试状态；
- GP22 设计批准不等于 React 运行时或规划功能已经完成；现有 GP21 Token 与界面标识在独立迁移 Issue 完成前只能描述实现滞后。

## 6. 文件与文档

- `materials/`：只读学校原件；
- `PreDesign/idea-archive/`：方向共识、案例和历史未决事项；
- `docs/adr/`：长期架构决策；
- `docs/project/`：当前决策、进度与实施路线；
- `deliverables/`：阶段报告和答辩交付；
- `outputs/`、`tmp/`：生成物和临时文件，不进入历史。

不得提交 `node_modules`、缓存、`dist`、`*.tsbuildinfo`、生成的 Vite 配置 JS/DTS、模型权重、可重新下载的大视频或任何密钥。

每个可独立实现和关闭的 Bug 使用独立 Issue；路线文档只保留 Issue 引用和优先级。

## 7. 验证矩阵

| 修改范围 | 最低验证 |
| --- | --- |
| 文档/提示词 | 路径、链接、术语、JSON 或 Markdown 结构检查 |
| 前端组件/状态 | 前端 lint、相关测试、前端 build |
| 后端模型/API | Ruff、后端 pytest；涉及运行态时运行相应 Smoke |
| 跨层契约/依赖 | `pnpm check`，必要时 `pnpm smoke` |
| 性能/动画/Web3D | 构建 + 目标电脑手工帧率和降级验证 |

报告必须区分“命令通过”“手工验证”“未验证”。现有 `pnpm smoke` 在 Issue #14 完成前只代表旧 Mock 链验证。

## 8. 禁止事项

- 不得根据旧原型自动扩大毕业设计范围；
- 不得为追求技术数量引入无法验收的基础设施；
- 不得把条件性地图、数据库、Vision、Web3D、AI 或发行工作写成核心硬依赖；
- 不得把模拟事件描述为真实识别；
- 开始前检查仓库状态和相关项目文档，不覆盖来源未确认的已有改动；
- 不得在测试失败时删除测试或降低断言来制造通过；
- 不得未经授权推送、发布或改变 GitHub 可见性。

# 实施路线与验收依赖

- 状态：当前可执行工作队列
- 最后更新：2026-08-02
- 项目定位：本地/内网、多用户、可审计的毕业设计平台型多屏 HMI，持续迭代至 2027 年 4 月
- 当前实际状态与验证证据见 [`PROJECT_PROGRESS.md`](./PROJECT_PROGRESS.md)
- 范围与非目标见 [`DECISION_BASELINE.md`](./DECISION_BASELINE.md)
- 已确认的长期与短期方向见 [`PROJECT_DIRECTION.md`](./PROJECT_DIRECTION.md)

## 1. 执行原则

- GP22 资产引入和持续 Figma intake 是当前最高优先级；平台基础设施与其并行推进。
- 只有“不完成就无法保证基本正确性”或已确认属于 2027 年 4 月最终验收的事项才是长期硬依赖。
- 优先保持状态权威、错误恢复和设计到代码的一致性，再逐步建设平台能力。
- 每个可独立实现、关联 PR 和关闭的问题必须有独立 Issue。
- Tracker/路线文档只组织优先级，不长期保存未编号 Bug。
- 规划能力只有具备运行实现、测试或可重复步骤以及展示证据后，才能标记为完成。
- GP22 第一轮视觉闭环可以先于真实地图、VehicleVision、AI 语音和 Web3D 完成；但这些已确认的最终验收能力不能永久留在条件性队列。

## 4. P1 — 核心产品正确性与答辩功能

### Issue #7 — Overview 严格只读

- 只修命令边界；
- 不进行视觉重设计；
- 不再依赖新的 Figma 画面或三档视觉验收才能开始。

### Issue #12 — 风险仲裁一致性

- 统一 Cluster、HUD、Center 和 Passenger 的主要风险选择；
- 媒体抑制必须与后端“任何 active/acknowledged critical 风险”规则一致。

### Issue #17 — 独立 Control 端点

- `/control` 不再回退为 Center；
- 提供主题、系统模式、模拟场景和 reset 的最小答辩控制；
- 更复杂诊断、历史时间线和外部服务指标不是本 Issue 的前置。

### Issue #19 — WebSocket 与运行时合同容错

- 非法 JSON 或不完整快照不能进入 Store；
- 连接不能在数据已损坏时继续显示为健康；
- 支持无需刷新页面的安全恢复。

## 5. P2 — 近期可靠性、内部权限与验证

### Issue #18 — 导航 Data Health 一致性

本地降级路线、Provider 状态和导航健康值必须使用一致转换规则。该 Issue 不实现真实高德地图。

### Issue #13 — 本地端点权限边界

- 服务端拥有的请求/连接上下文决定端点权限；
- 客户端不能仅修改 JSON 字段升级为其他端点；
- Control 默认禁用或只在显式本地配置下启用；
- 不建设 OAuth、SSO、JWT 平台、多租户或生产车辆 PKI。

### Issue #14 — `gp05.v1` 真实进程 Smoke

硬依赖仅有 Issue #11 的 reset/reconnect 行为。

Issue #12 不阻塞传输收敛测试，Issue #13 也不阻塞当前允许命令和当前拒绝行为的 Smoke。#13 完成后可扩展负向权限场景，但不应让核心多客户端测试长期等待。

## 6. 核心稳定后的主要创新

### 一个真实 VehicleVision 场景

核心 HMI 稳定后，优先实现一个可重复验证的驾驶员疲劳/分心场景：

- 摄像头或授权视频输入；
- 明确的正例、负例和边界用例；
- 候选事件进入风险/策略层；
- 四屏响应 `active → acknowledged → resolved`；
- 无摄像头、缺模型和低置信度时有可见降级；
- 不把手动注入或预设动画描述成真实推理。

该场景是推荐的毕业设计主要技术差异化方向，但不应在 P0/P1 缺陷修复前扩大为通用 Vision 平台。

## 7. 最终验收能力与条件性增强

以下能力已经纳入 2027 年 4 月最终验收，必须建立独立、有边界的 Issue 和证据：

- 真实地图/地点搜索、Provider 适配层、凭据隔离和本地 fallback；
- PostgreSQL 持久化、审计历史、备份恢复和权限查询；
- 一个真实 VehicleVision 疲劳/分心场景；
- 受限 AI 语音白名单 command、确认和失败反馈；
- 四屏多显示启动与部署编排；
- 后置 Web3D 懒加载、权威状态绑定和静态 fallback。

以下仍是可选增强或外部要求触发项：

| 工作 | 条件 |
| --- | --- |
| 第二个及更多 Vision 场景 | 首个真实场景稳定且收益高于剩余成本 |
| Electron/Tauri 封装 | 浏览器多屏启动不能满足现场部署 |
| Windows 签名或 macOS 公证 | 准备向外部分发正式安装包 |
| 正式认证、多租户、高可用 | 服务进入公共云、不可信网络或复杂共享部署 |
| 容器化 | 脚本安装不能满足可复现部署 |

条件性增强不得反向取消已确认的最终验收能力。

## 9. 当前不计划事项

当前项目不建设：

- 企业 SSO、多租户账户体系；
- 公共互联网 API 网关、WAF 或通用 SSRF 平台；
- 量产车 PKI、CAN 安全网关或功能安全认证；
- ROS2、CARLA、MQTT 或通用消息中间件；
- 多节点高可用和分布式一致性；
- 全平台安装包和完整软件供应链证明；
- 数字人、情绪识别、XR 或复杂 LLM 自主驾驶决策。

若未来定位发生变化，应通过新的决策 Issue 重新评估，而不是在当前 Backlog 中提前建设。

6. 一个真实疲劳/分心 VehicleVision 场景；
7. 受限 AI 语音；
8. 四屏多显示启动与部署编排；
9. 后置 Web3D；
10. 根据剩余时间再评估第二 Vision 场景、桌面封装或正式发行。

## 11. 当前核心验收标准

进入答辩功能冻结前，应至少证明：

- 四个产品端点和 Control 使用同一权威 session/revision；
- Overview 不可发送业务命令；
- 导航接力、模拟风险处置和副驾协作可确定性重演；
- 新 session、reset、断线和非法消息可以安全恢复；
- 前后端对主要风险和媒体抑制没有矛盾；
- 真实进程四客户端 Smoke 在 CI 通过；
- Mock、真实、降级和未实现能力被明确区分；
- README、方向、进度、路线和代码事实一致；
- 设计资产版本、数据库迁移/恢复、权限、审计和最终演示均有证据。

## 12. 运行质量基线

- 四屏启动和部署步骤可重复；
- 本地命令确认延迟目标为 P95 ≤ 500 ms；
- WebSocket 断线后自动恢复目标为 ≤ 5 秒；
- 共享车辆状态不得出现屏间分叉；
- 命令、风险和恢复事件审计完整率为 100%；
- 关键错误必须有日志、告警或可见的安全降级。

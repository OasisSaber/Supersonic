- 状态：`GP21-VISUAL-INTERACTION-FROZEN`
- 最后更新：2026-07-31
- 项目标题：**《智能座舱多屏协同 HMI 设计与交互原型》**
- 当前形态：本地、单用户、可信环境的毕业设计原型
- 当前设计主版本：`GP21-VISUAL-INTERACTION-FROZEN`
- 运行时协议名：`gp05.v1`，保留用于合同和历史实施追溯

本文定义当前项目范围、工程标准、核心验收和非目标。当前进度与开放缺陷见 [`PROJECT_PROGRESS.md`](./PROJECT_PROGRESS.md)，可执行顺序见 [`IMPLEMENTATION_ROADMAP.md`](./IMPLEMENTATION_ROADMAP.md)。历史 GP04/GP05 设计过程、旧实施计划和更宽的能力设想继续保留在 Git 历史、设计资料和归档文档中，但不得覆盖本文的当前范围。

## 1. 项目定位与信任模型

本项目用于作者本人的毕业设计开发、答辩演示和技术审查。默认运行方式是：

- 一台 Windows 主机；
- 一个 FastAPI 进程；
- 多个本地浏览器页面分别显示 Cluster、HUD、Center、Passenger、Overview 和 Control；
- 本地可信操作者；
- 不对公共互联网提供服务；
- 不提供多用户账户、租户或第三方插件执行环境。

因此，当前工程必须保证应用内部权限、状态一致性、错误恢复和素材隐私，但不机械套用公共云、企业多租户或量产车辆系统的完整治理标准。

当前不以以下内容作为开发阻断项：

- 企业 SSO、OAuth、通用 JWT 平台或多租户；
- 公共 API 网关、WAF、通用 SSRF 防护平台；
- 高可用、多节点状态复制和分布式一致性；
- 量产车辆 PKI、CAN 安全网关或功能安全认证；
- Windows 代码签名、macOS 公证和全平台安装包；
- 容器级、虚拟机级或系统级隔离；
- 完整软件供应链证明。

只有在公开部署、安装包分发、多人共享或学校交付明确要求出现时，才通过独立 Issue 重新评估。

## 2. GP21 冻结含义

- GP21 是当前唯一视觉与交互参考；
- Figma/Make 冻结表示视觉意图、信息层级和主要交互方向已获批准；
- **视觉冻结不等于 React 运行时、数据链、恢复能力或全部规划功能已经完成**；
- React 是最终运行表现，FastAPI/WebSocket 是共享业务状态真相；
- 工程实现不得无记录地偏离已冻结的四屏职责和设计 Token；
- 修复端点权限、状态完整性、可访问性或协议阻断，不需要先创建新的 GP 视觉版本；
- 真正改变布局、端点职责、核心流程或视觉语言时，才需要解冻评估。

## 3. 核心产品范围

四个产品端点同等重要，但职责不同：

| 端点 | 核心职责 | 明确限制 |
| --- | --- | --- |
| Cluster | 车速、续航、路线状态、风险等级和处置状态 | 基本只读，不承担复杂设置或娱乐 |
| HUD | 最低认知负荷的下一步驾驶行动和最高优先级提示 | 只读，无菜单、长文本和持续干扰动画 |
| Center | 路线规划、必要的车辆/环境控制、风险详情和确认操作 | 不复制仪表全部内容 |
| Passenger | 娱乐、旅程协作、隐私和许可的座舱控制 | 不拥有驾驶关键控制 |
| Overview | 四屏只读编排和答辩观察 | 不发送产品业务命令 |
| Control | 本地答辩场景、主题、系统模式、重置和最低限度诊断 | 不是车内产品端点，不绕过 FastAPI 权威状态 |

当前核心三条工作流：

1. **导航接力**：Center 选择并确认本地确定性路线，Cluster/HUD 获得对应摘要；
2. **风险接管与恢复**：模拟或未来真实候选风险经过状态机后驱动四屏，Passenger 抑制娱乐；
3. **副驾协作**：Passenger 控制媒体、隐私和旅程建议，驾驶端只接收必要共享状态。

Profile、主题同步、连接恢复和 Control 操作是系统流程，不替代上述三条产品工作流。

## 4. 运行时真相与协议

- FastAPI 是运行时唯一权威业务状态源；
- 前端只保留输入焦点、临时弹层等瞬时 UI 状态；
- HTTP 用于命令和资源，WebSocket 用于持续全量 snapshot；
- 客户端不得把未确认命令或本地推测值当作最终业务状态；
- 重连时获取最新完整 snapshot，不能依赖重放旧事件恢复；
- `command`、`event`、`snapshot` 是协议的三类消息；
- 消息包含版本、消息 ID、correlation ID、时间、来源与目标信息；
- 端点权限必须最终由服务端拥有的请求或连接上下文决定，不能只信任客户端自报字段；
- Mock、真实来源和手动注入必须具有可见且可测试的来源标签。

当前已知协议和运行时缺陷全部使用独立 Issue 跟踪，不再在本文保存未编号 Bug。

## 5. 数据健康与降级

- 数据域使用 `fresh`、`stale`、`offline` 表达健康状态；
- stale 显示最后权威值和状态提示，offline 明确说明不可用；
- 不用随机值或客户端估算掩盖断线；
- 本地路线是确定性降级数据，不冒充实时地图规划；
- 风险手动注入和 `simulated_event` 只验证后续联动，不冒充真实视觉识别；
- reset 创建新的 session，并使所有在线端点收敛到一致的新 snapshot；
- 无效或损坏的 WebSocket 数据不得进入 Store，也不能让页面继续显示为健康连接。

## 6. 当前工程优先级

### 核心正确性

- Session/revision/reset 一致性；
- Overview 只读；
- 统一风险仲裁和媒体抑制；
- 独立 Control 页面；
- WebSocket 和运行时合同容错；
- 导航 route/provider/data-health 一致性；
- 本地端点权限边界；
- 真实进程多客户端 Smoke。

对应 Issue 和顺序以路线文档为准。

### 主要毕业设计创新

核心 HMI 稳定后，优先实现**一个真实驾驶员疲劳/分心 VehicleVision 场景**，形成：

`摄像头或授权视频 → 候选事件 → 风险策略 → FastAPI 权威状态 → 四屏联动 → 恢复`

该场景需要：

- 正例、负例和边界用例；
- 明确的持续时间、解除和冷却规则；
- 摄像头、模型缺失和低置信度降级；
- `LIVE CAMERA`、`VIDEO INFERENCE` 和 `SIMULATED EVENT` 来源区分；
- 不保存连续原始视频，不做身份识别或情绪推断。

第二、第三个 Vision 场景是推荐增强，不是首个真实场景的前置条件。

## 7. 条件性能力

以下能力只有触发条件成立时才进入实施队列：

### 真实地图

当前本地确定性路线足以验证跨屏导航接力。只有答辩必须展示真实地点搜索时，才实现高德 Provider、凭据管理和失败降级。

### 持久化

当前内存状态足以完成核心演示。只有指导教师、论文论证、行程报告或历史查询明确需要数据库时，才实施持久化。届时可以选用与项目规模匹配的方案；MySQL、Alembic 和完整审计链不是默认硬要求。

### Web3D

Web3D 只能作为 Center 的增强展示，必须懒加载并有静态 fallback。它不参与导航、风险判定或权威状态，也不阻塞核心答辩。

### AI 语音

AI 语音只复用已有受约束 command。核心状态、恢复、Smoke 和主要创新证据完成后再评估。数字人、情绪模型和复杂自主决策不进入当前范围。

### 桌面封装与发行

浏览器路由、多显示器和脚本启动是当前基线。只有现场部署确实需要时才评估 Electron/Tauri；签名、公证和公共发布治理只在正式分发时实施。

## 8. 性能标准

性能分为基本验收和目标机加分指标：

### 基本验收

- 核心驾驶信息在目标机上持续可读、无明显卡顿；
- 普通 HMI 目标至少稳定 60 FPS；
- 关键告警和命令反馈无可感知长停顿；
- Web3D、Vision 或外部服务失败不能阻断 Cluster、HUD 和告警；
- 断线和恢复时间通过可重复步骤记录。

### 目标机加分

在 RTX 4070 Laptop 和高刷新率显示器上，可进一步记录：

- 120/144 FPS HMI 表现；
- 1% Low 和帧时间；
- Web3D 60 FPS；
- Vision 20–30 FPS；
- 跨屏同步和事件响应延迟。

这些高端指标用于性能报告和答辩加分，不作为修复状态错误或完成核心工作流的前置条件。

## 9. 测试与完成定义

能力只有同时满足以下条件，才能标记完成：

1. 当前 `main` 中存在可运行实现；
2. 有自动化测试或可重复的手工步骤；
3. 有与能力声明相匹配的展示证据；
4. Mock、真实、降级和未实现部分标记准确；
5. README、进度和 Roadmap 已同步。

核心测试层：

- 合同和状态转换测试；
- 前端 Store、组件和通信容错测试；
- FastAPI authority/API/WebSocket 测试；
- 真实进程多客户端 Smoke；
- 需要视觉或性能结论时，再进行目标机人工验证。

`pnpm check` 当前覆盖 Lint、单元测试和构建。现有 `pnpm smoke` 在 Issue #14 完成前只代表旧 Mock 链验证。

## 10. 核心答辩冻结条件

进入答辩功能冻结前，至少需要：

- 四个产品端点和独立 Control 使用同一权威 session/revision；
- Overview 严格只读；
- 三条本地核心流程可以确定性重演和 reset；
- 风险显示与媒体抑制前后一致；
- 重启、断线、无效消息和降级可以安全恢复；
- 真实进程四客户端 Smoke 在 CI 通过；
- 至少一个主要创新方向具有真实、可重复证据，优先选择驾驶员疲劳/分心 Vision；
- 文档与代码能力一致。

真实地图、MySQL、Web3D、多个 Vision 场景和 AI 语音不属于默认核心冻结的硬依赖。

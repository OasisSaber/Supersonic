## 1. 项目定位与信任模型

本项目用于作者本人的毕业设计开发、答辩演示和技术审查。默认运行方式是：

- 一台 Windows 主机；
- 一个 FastAPI 进程；
- 多个本地浏览器页面分别显示 Cluster、HUD、Center、Passenger、Overview 和 Control；
- 本地/内网用户，按 `admin`、`operator`、`viewer` 角色执行最小权限操作；
- 不对公共互联网提供服务；
- 不默认提供公共 SSO、复杂多租户或第三方插件执行环境。

因此，当前工程必须保证应用内部权限、状态一致性、错误恢复、审计和素材隐私，但不机械套用公共云、企业多租户或量产车辆系统的完整治理标准。

当前不以以下内容作为开发阻断项：

- 企业 SSO、OAuth、通用 JWT 平台或复杂多租户；
- 公共 API 网关、WAF、通用 SSRF 防护平台；
- 高可用、多节点状态复制和分布式一致性；
- 量产车辆 PKI、CAN 安全网关或功能安全认证；
- Windows 代码签名、macOS 公证和全平台安装包；
- 容器级、虚拟机级或系统级隔离；
- 完整软件供应链证明。

只有在公开部署、安装包分发、多人共享或学校交付明确要求出现时，才通过独立 Issue 重新评估。

- **设计批准不等于 GP22 React 运行时、数据链、恢复能力或全部规划功能已经完成**；
- 当前源码中的 GP21 Token 和界面标识只能描述尚未迁移的实现，不得反向覆盖 GP22 设计决策；
- React 是最终运行表现，FastAPI/WebSocket 是共享业务状态真相；

## 3. 核心产品范围

四个产品端点同等重要，但职责不同：

| 端点 | 核心职责 | 明确限制 |
| --- | --- | --- |
| Cluster | 车速、续航、路线状态、风险等级和处置状态 | 基本只读，不承担复杂设置或娱乐 |
| HUD | 最低认知负荷的下一步驾驶行动和最高优先级提示 | 只读，无菜单、长文本和持续干扰动画 |
| Center | 路线规划、必要的车辆/环境控制、风险详情和确认操作 | 不复制仪表全部内容 |
| Passenger | 娱乐、旅程协作、隐私和许可的座舱控制 | 不拥有驾驶关键控制 |
| Overview | 四屏只读编排和答辩观察 | 不发送产品业务命令 |
| Control | 本地答辩场景、主题、系统模式、重置和最低限度诊断 | 不是车内产品端点，不绕过 FastAPI 权威状态 |

当前核心三条工作流：

1. **导航接力**：Center 选择并确认本地确定性路线，Cluster/HUD 获得对应摘要；
2. **风险接管与恢复**：模拟或未来真实候选风险经过状态机后驱动四屏，Passenger 抑制娱乐；
3. **副驾协作**：Passenger 控制媒体、隐私和旅程建议，驾驶端只接收必要共享状态。

Profile、主题同步、连接恢复和 Control 操作是系统流程，不替代上述三条产品工作流。

## 4. 运行时真相与协议

- FastAPI 是运行时唯一权威业务状态源；
- 前端只保留输入焦点、临时弹层等瞬时 UI 状态；
- HTTP 用于命令和资源，WebSocket 用于持续全量 snapshot；
- 客户端不得把未确认命令或本地推测值当作最终业务状态；
- 重连时获取最新完整 snapshot，不能依赖重放旧事件恢复；
- `command`、`event`、`snapshot` 是协议的三类消息；
- 消息包含版本、消息 ID、correlation ID、时间、来源与目标信息；
- 端点权限必须最终由服务端拥有的请求或连接上下文决定，不能只信任客户端自报字段；
- Mock、真实来源和手动注入必须具有可见且可测试的来源标签。

当前已知协议和运行时缺陷全部使用独立 Issue 跟踪，不再在本文保存未编号 Bug。

## 5. 数据健康与降级

- 数据域使用 `fresh`、`stale`、`offline` 表达健康状态；
- stale 显示最后权威值和状态提示，offline 明确说明不可用；
- 不用随机值或客户端估算掩盖断线；
- 本地路线是确定性降级数据，不冒充实时地图规划；
- 风险手动注入和 `simulated_event` 只验证后续联动，不冒充真实视觉识别；
- reset 创建新的 session，并使所有在线端点收敛到一致的新 snapshot；
- 无效或损坏的 WebSocket 数据不得进入 Store，也不能让页面继续显示为健康连接。

## 6. 当前工程优先级

### 核心正确性

- Session/revision/reset 一致性；
- Overview 只读；
- 统一风险仲裁和媒体抑制；
- 独立 Control 页面；
- WebSocket 和运行时合同容错；
- 导航 route/provider/data-health 一致性；
- 本地端点权限边界；
- 真实进程多客户端 Smoke。

对应 Issue 和顺序以路线文档为准。

### 主要毕业设计创新

核心 HMI 稳定后，优先实现**一个真实驾驶员疲劳/分心 VehicleVision 场景**，形成：

`摄像头或授权视频 → 候选事件 → 风险策略 → FastAPI 权威状态 → 四屏联动 → 恢复`

该场景需要：

- 正例、负例和边界用例；
- 明确的持续时间、解除和冷却规则；
- 摄像头、模型缺失和低置信度降级；
- `LIVE CAMERA`、`VIDEO INFERENCE` 和 `SIMULATED EVENT` 来源区分；
- 不保存连续原始视频，不做身份识别或情绪推断。

第二、第三个 Vision 场景是推荐增强，不是首个真实场景的前置条件。

## 7. 最终平台能力

以下能力已经纳入 2027 年 4 月最终验收，实施顺序可以分阶段，但不得在最终验收时豁免：

### 真实地图

实现真实地点搜索时使用 Provider 适配层，凭据只在服务端或受控配置中管理，并保留本地确定性路线和静态结果作为失败降级。

### 持久化

PostgreSQL 是正式平台数据库。它持久化用户、角色、权限、会话、命令审计、风险事件、恢复结果、必要的状态快照和系统配置；FastAPI/WebSocket 仍然是实时状态唯一权威来源。数据库迁移、备份恢复和审计查询属于毕设交付范围。

### Web3D

Web3D 后置到核心平台稳定后实施，必须懒加载、绑定至少一类权威状态、支持静态 fallback。它不参与导航、风险判定或权威状态判定，但属于最终验收门槛。

### AI 语音

AI 语音只复用白名单 command，必须有明确确认、失败反馈，不能直接写入独立业务状态或做自主驾驶决策。核心状态、恢复、Smoke 和主要创新证据完成后实施，但属于最终验收范围。数字人、情绪模型和复杂自主决策不进入当前范围。

### 桌面封装与发行

浏览器路由、多显示器和脚本启动是当前实现基线；最终交付必须提供可重复的四屏启动与部署编排。只有现场部署确实需要时才评估 Electron/Tauri；签名、公证和公共发布治理只在正式分发时实施。

### 多用户与权限

- 最低角色为 `admin`、`operator`、`viewer`；角色对应的管理、操作和只读界面属于最终验收范围；
- 登录、会话撤销、最小权限和命令审计必须同时由服务端和前端可见界面支持；
- 默认面向本地/内网，不建设公共 SSO、复杂多租户或远程开放运维权限。

### 安全与隐私

- 密码使用 Argon2id 等慢哈希，秘密不进入仓库；
- 审计记录追加式保存并可追溯；
- VehicleVision 原始视频/音频默认只短暂处理，不保存连续原始媒体，不做身份识别或情绪推断；
- 地图、语音、模型和 Web3D 外部服务不可用时，必须安全降级。

## 8. 性能标准

性能分为基本验收和目标机加分指标：

### 基本验收

- 核心驾驶信息在目标机上持续可读、无明显卡顿；
- 普通 HMI 目标至少稳定 60 FPS；
- 关键告警和命令反馈无可感知长停顿；
- Web3D、Vision 或外部服务失败不能阻断 Cluster、HUD 和告警；
- 断线和恢复时间通过可重复步骤记录。

### 平台运行质量基线

- 四屏启动和部署步骤可重复；
- 本地命令确认延迟目标为 P95 ≤ 500 ms；
- WebSocket 断线后自动恢复目标为 ≤ 5 秒；
- 共享车辆状态不得出现屏间分叉；
- 命令、风险和恢复事件审计完整率为 100%；
- 关键错误必须有日志、告警或可见的安全降级。

### 目标机加分

在 RTX 4070 Laptop 和高刷新率显示器上，可进一步记录：

- 120/144 FPS HMI 表现；
- 1% Low 和帧时间；
- Web3D 60 FPS；
- Vision 20–30 FPS；
- 跨屏同步和事件响应延迟。

这些高端指标用于性能报告和答辩加分，不作为修复状态错误或完成核心工作流的前置条件。
